## 时间与确认数据契约

### 一次性生产快照

- `time`：旧格式原样保留，普通信号为极值 K 线标签，中枢沿为触及 K 线标签，可能只到日期。中枢沿 price 是触及根收盘价，不是沿上的成交价。不能解释为信号发现/成交时间。
- `signal_bar_time`：同一个标签的带时区 ISO 表达；`bar_time_role=extreme|touch` 区分语义。
- `extreme_bar_time`：普通信号为极值根标签，中枢沿为 null。不是精确到分钟的根内极值发生时间；OHLC 无法提供根内路径。
- `first_seen_time`、`confirmed_time`、`earliest_executable_time`：均为 null。
- `timing_evidence=historical_snapshot_only`、`bar_completion=unknown`、`backtest_eligible=false`。
- `touch_confirmed`：中枢沿为快照内触及谓词的旧布尔值；其他类别 null。不保证收盘最终值。
- `structure_confirmed`：普通/BC 信号沿用当前算法的线段确认布尔；中枢沿 null（没有稳定的中枢来源 ID，不能从 `confirmed=True` 反推）。
- `entry_confirmed`：全部 null，P0 未定义任何新的交易入场规则。
- `confirmation_scope`：`edge_touch_in_snapshot` 或 `segment_in_snapshot`。后者可来自特征分型，也可来自 `by_break` 近似规则；不承诺未来不重绘。

所有新增字段是附加元数据，不参与现有识别或评分。`scripts/build_data.py` 保留信号附加字段，图表导出使用同一契约。
旧前端的 confirmed 筛选仍是旧筛选，不等于“可入场筛选”；列表、详情和评分解释对中枢沿明确标注触及。
旧数据没有新增字段时仍可展示，前端按类型识别中枢沿。

### 市场环境

`regime` 保留 benchmark、bear、close、sma200（后两项只在有效计算时存在）。
新增 `status=unknown|bear|non_bear`、`known`、`bar_completion`。
失败/缓存无证据：`status=unknown, known=false, bear=false, error=...`。
保留 boolean bear 是为了兼容旧读取方，**旧读取方若使用 not bear 仍不安全，必须迁移**。
已算出但未证实完成的日线可保留测量状态，不能成为新策略许可。

`regime_decision()` 输出 `regime_state` 三态和 `new_long_environment=unknown|blocked|permitted`：
熊市阻止新增长仓；已完成且已知的非熊环境仅通过环境这一道检查；失败、旧记录、错误、完成状态未知均 unknown。
生产流水线目前没有可审计的基准完成清单，所以非熊观测的策略上下文仍为 unknown。
旧 `regime_paused` 仅保留原有熊市提示语义；没有借此改变旧信号列表。
`permitted` 不等于可下单，还需要 P1 时序、方向、风险与执行门槛。

## 逐根重放契约与可复现样例

```sh
python -m scripts.replay_p0_example --output /tmp/p0-replay.json
python -m unittest tests.test_signal_safety tests.test_chan2 tests.test_pivot_edge tests.test_score
```

样例用 numpy 固定种子 3 构造 360 根连续合成 30 分钟 OHLC，UTC 标签是开盘时间，
显式假定每根在标签 +30 分钟完成并立刻可用。不是交易所日历或真实实时接收证据。
输出应有首次出现、结构确认、消失、执行窗口四类事件；测试不依赖固定收益或交易次数。

`replay(df, available_at=..., complete=..., open_times=..., level='30m')`：

1. 要求带时区、严格递增的标签与可用时间；OHLC 缺失/无效立即报错，不进行 dropna 拼接。
2. `complete` 每根显式 bool；未完成尾根完全不进入计算；内部未完成根拒绝，不能跳过后拼接。
3. 第 i 次分析只看到当时已经完成的前缀。`first_seen_time` 是该重放数据集第一次观察该候选的 available_at，不能被极值标签替代。
4. 候选 ID 由信号类别（PRE 去前缀）、极值标签、价格、中枢边界、kind 组成；重复身份拒绝，需要补充来源 ID。极值/价格/边界变化作为消失与新候选；消失后再现是新 episode，不跨缺席窗口合并。
5. `confirmed_time` 仅记录重放中首次观察到 structure_confirmed 的时刻；不代表真实生产第一次确认。确认回退会追加 `confirmation_revoked`，再次确认也追加事件，历史首次确认时间不被覆盖。中枢沿不写结构确认时间。
6. 原始出现事件与历史快照不会因后续突破/新触及/重绘而删除。`disappeared` 只表示当前前缀中缺席，不推断具体原因或已经成交的交易可取消。
7. 若提供有证据的 `open_times`，只在后续观察到的开盘严格晚于发现时刻时，记录 `execution_window`。边界相等时保守跳过该开盘。这是声明的严格晚于模型，**不是绝对最早市场成交时间、成交证明或入场确认**。无开盘证据则执行时间留空。手续费、滑点、跳空、停牌、涨跌停、T+1 均未模拟。
8. 预加载下一根的 Open 价格不作为当前检测输入；执行窗口事件仅在该根到来时追加。发现时间后的不可交易标记必须由后续策略层处理。

该工具验证“当前检测器在给定历史 K 线版本上的因果识别”，不能恢复真实盘中修订、供应商接收延迟、首次生产轮询时间。
完整历史与前缀结果差异是审计事实，不能用最终回算结果替换历史账本。

## 波段架构与 P1 实施建议（本次未实施）

建议：供应商 OHLC + 交易所日历/版本归档 → 完成且可用的 K 线流 → 各周期前缀分析 →
不可变事件账本 → 日线方向与市场环境 as-of join → 30 分钟候选筛选 → 风险/执行模拟 → 样本外评估。

P1 候选筛选器单独 PR：

- 只使用在 30 分钟识别时刻已可用的完整日线方向；绝不拿当日盘中日线或当周最终周线回填。
- unknown 环境、缺行情、日历/时间语义不明时不新增候选；区分 blocked 与 unknown，保留原因。
- 单独定义哪些传统/BC/中枢沿类别允许进入候选、怎样从结构观察升级到入场确认；PRE 与触及不自动放行。
- 定义候选有效期、重绘撤销、同一中枢去重、冲突处理；不得删去已发生的模拟成交。
- 定义下一可交易时点、滑点、费用、跳空止损、A 股 T+1/涨跌停/停牌、组合风险与仓位。
- 对不同供应商的标签、复权和交易时段先做契约测试；归档原始数据与配置版本。
- 先固定假设再评估，使用独立时期/样本外与敏感性分析；现有代码注释中的收益数字不构成经验证证据。

## 仍未验证的假设 / 验收边界

近似缠论结构是否有预测能力、日线方向与 30 分钟入场的组合有效性、评分是否能排序风险收益，均未知。
本 PR 无回测收益、胜率、可交易性验证。重放单周期，不包含跨周期策略回测或线上增量持久化。
不改 VPS、IBKR、密钥管理，不合并 main。审核后才能决定是否安排 P1 或单独部署。
