# 2026-10-22 手机界面精修

保留五个业务页面、API、筛选规则、图表和通知链路。根据用户要求移除全部口号式大标题、介绍文案和装饰编号；功能名称保持可见。

## 采用的技能

- [Apple Design](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md)：触控按下即时反馈、空间方向、文字层级、减少动态效果和高对比偏好。
- [Emil Design Engineering](https://github.com/emilkowalski/skills/blob/main/skills/emil-design-eng/SKILL.md)：高频筛选不重播入场动画、快捷键即时打开、只过渡明确属性、鼠标悬停限制在精确指针设备。
- [Taste Skill](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md) 的 app-screens 流程：先看真实业务、记录改前截图、选择方向、检查浏览器、逐屏复核。没有采用营销落地页流程。

方向：`true-black-flat`，seed `456655088`，无重抽。保留既有墨绿纸白主题及系统字体，采用其明度区分表面、反色主按钮与中性导航的原则。保留五项底部导航以满足手机单手使用；不套用桌面终端。产品特征来自四周期方向标签和“信号→依据”的研究路径。买卖及中枢沿颜色保留业务含义，不当成装饰色。

## 各页首先回答的问题

| 页面 | 问题 |
| --- | --- |
| 信号 | 哪些信号值得进一步核对？ |
| 标的 | 某个标的的四个周期方向是否一致？ |
| 持仓 | 当前数量、成本、现价与浮盈亏是什么？ |
| 大环境 | 哪些宏观变化提供背景？ |
| 说明 | 评分、确认状态与数据有哪些边界？ |

## 修改对照

| Before | After | Why |
| --- | --- | --- |
| 五页都有口号、说明及01–05编号 | 删除整块，保留功能标题 | 首屏优先展示真实内容，符合用户明确要求 |
| 9–10px 次要文字、过期整行降透明度 | 次要文字至少11–12px，保留“已过期”语义文字 | 提升可读性，不靠降低整行对比度表达状态 |
| 手机标的双列、信息拥挤 | 单列，名称与价格同层、周期方向下一层 | 允许中文全名和交易代码完整显示 |
| 持仓沿用最小860px表格 | 手机改为两层列表，五字段都保留 | 无须横向寻找成本与盈亏，桌面仍是表格 |
| 每次筛选重复行入场动画 | 列表即时更新，按钮保留短按压反馈 | 高频操作更直接 |
| 搜索框小字号 | 手机16px，明确搜索键 | 避免iOS聚焦时自动放大 |
| 主按钮和多个导航都强调品牌色 | 反色主按钮，中性选中导航 | 数据语义色更突出 |

## 验证

- Playwright：手机筛选、焦点循环、Escape、快捷键、图表、深浅主题、设置、持仓及图表、宏观术语、五页导航、A股名称与代码搜索、接口失败和重试、图表请求竞态。
- 原有320/375/390/430/768/900/1024/1440宽度检查通过；新增第一条信号在手机屏幕上方60%以内、iOS输入16px及持仓字段全部位于手机可视宽度的检查。
- 深浅两主题逐页截图检查，测试截图使用明确的本地测试快照，不用于替换线上数据。
- Taste浏览器检查：改前3 FAIL / 3 WARN；改后0 FAIL / 0 WARN（1440、768、390）。源码lint无FAIL；静态扫描把 `backdrop-filter:none` 及无阴影的选中下划线也记为WARN，已核对计算样式。真实投影只用于浮层。
- JS语法、术语回归、`git diff --check`。

没有新增依赖，没有模拟交易、支付或注册流程，也没有引入外链字体或图片。
