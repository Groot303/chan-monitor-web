# 题材接力观察 V1

## 要回答的问题

某个题材集中开板之后，其他题材的封板样本是否增加，是否比此前同长窗口增加得更快？这是涨跌停观察池内的时序描述，不证明资金从A流入B，不产生下单、通知、交易收益或因果评分。没有接入全市场板块涨幅宽度、成交额增速、委托队列或实际账户资金流向。

入口：A股底部“接力”，桌面“接力观察”。选择已观察的事件及5、15、30分钟窗口；显示其他题材已匹配封板净变化、前后差，以及净增/净减名单、新见封板、回封、开板与离池的实际采样证据。全池封板净变化用作市场整体活跃的背景，不能直接当作某题材的承接金额。

## 明示的规则

- 触发：相邻有效快照出现sealed→broken，同一主要题材180秒内至少2只不同股票；归因使用开板前已可见的证据。首份快照中已经炸板者不作为触发，同一股票重复开板不凑够两只。
- 防重复：同一题材30分钟内最多触发一次，页面返回最近12个事件。阈值是第一版研究口径，并非已经验证的最优参数。
- 时间：观察起点为确认第二只不同股票开板的快照接收时间，真实发生在采样之间。不是供应商首封时间，也不是新策略当时已发出交易信号的证明。
- 窗口：固定5/15/30个连续自然分钟，必须处于真实XSHG交易日的同一上午或下午时段。跨午休、收盘不拼接，不换算为另一段交易分钟。
- 后窗：到达目标时间后，使用首个实际收到的结束快照，允许最多90秒采样误差，逐一展示实际端点。未到时为pending；缺少端点或相邻采样间隔超过90秒、不完整/冲突池等为incomplete，不用零或旧快照补齐。
- 前窗：寻找起点前同长区间的实际起始快照，允许最多90秒误差，要求全段连续、有效。同长前窗不足时，仍可显示有效后窗，但before_delta及acceleration为null，不能称为加速。

## 固定题材样本

每个窗口的比较区间为完整前窗起点至后窗终点；没有有效前窗时为事件起点至后窗终点。在区间里第一次实际见到一只股票时，锁定当时可核验的主要题材。后来新进入观察池的股票也在第一次出现时锁定，只向此后贡献样本；不会把后来的归因回填到过去。

第一次见到时无题材的股票，在本次比较中一直排除，即使后续补齐，也不能把补归因当成封板净增。名称发生异常变化者排除。已知题材后来变更者保持本比较区间的首次归属，并显示变更数量。行业及其他概念不用于重复分类。归因需同日、名称有效、来源事件时间及证据接收时间不晚于该快照。

因此每行是fixed_verified_cohort（固定的已核验样本），不等于完整板块。partial及unknown_stocks明确说明排除数量，不能因其他题材没有已匹配样本就声称它没有承接。不同窗口的固定样本集合可能不同，不宜把跨窗口数量差当作连续资金曲线。

## 透明计算

```text
net_delta = 后窗结束时该样本封板数 − 事件起点该样本封板数
before_delta = 事件起点该样本封板数 − 前窗起点该样本封板数
acceleration = net_delta − before_delta
```

acceleration只是同长窗口的数量差，非收益、金额或统计显著性。净增名单为结束封板且起点未封板者，净减名单反之；新见封板不等于生涯或当日首次涨停。开板、回封分别按不同代码去重，每只股票在两类里可各出现一次，两类数量不能相加代替净变化。离开两个池不冒充开板事件。

排序按其他题材已匹配净变化降序，再按前后差及名称排序，触发题材不混入“其他题材”。所有变化都可能由共同消息或市场整体变化造成，没有自动推断资金转移。

## 数据契约与兼容

只读`GET /api/cn/relay?date=YYYY-MM-DD`，响应schema=cn-theme-relay-v1，Cache-Control:no-store；无POST或执行入口。GET仅读取原始分钟快照并计算，不采集上游、不改写历史、不插入观察事件。旧快照的归因接收时间缺省时，使用该份实际快照接收时间，不能用当前theme_memory补充过去的题材。

结果包括规则、交易日、最近交易时段快照时间、事件及windows。window状态为pending、complete、incomplete、session_break；只有complete包含可比较rows。rows带样本起止数量、可空的前窗/前后差、涉及代码及时间；窗口附带实际端点、未知数量、改归因数量、全池背景变化和scope。

分钟快照只保留7个自然日，日末快照保留60天。超过分钟保留范围或该日没有采集时显示unavailable，不由每日一次性计算还原盘中接力。首版没有跨日胜率、复现频率或收益结论。

原有题材分布、梯队、炸板、昨日表现和关注清单继续使用原数据接口；仅增加第六个“接力”栏目。美股策略、账户、密钥、VPS部署配置未改变。

## 验证与可复现样例

```bash
python -m unittest tests.test_cn_relay
python -m unittest discover -s tests -p 'test_*.py'
python -m tests.check_paper_calendar
node tests/test_cn_relay_ui.cjs
```

明确测试夹具在tests/test_cn_relay.py：10:30（北京时间）机器人两只股票在相邻采样中开板；商业航天后续两只新见封板、一只回封，净封板+3，前窗0，前后差+3。纯夹具，不是实盘推荐或收益记录。API及浏览器使用独立临时SQLite；测试写入路由只在测试服务器存在。

覆盖未来快照截断、完成窗口不受后验归因影响、缺失与不完整来源、前窗不足、归因重分类、晚补归因、同股反复开合、首次基线、午休/跨日、真实交易日历、旧快照读取、只读接口、切日及断网保留、浅深主题和320/390/768/1440宽度。

后续可在取得足够日数的真实证据后研究事件条件下的重复性及对照组；接入全市场板块样本后再研究成交额增速、相对放量和上涨宽度。不能从当前计数直接推出真实资金来源或可交易收益。
