# 美股模拟盘自动止损

仅作用于美股模拟账户，不接入任何真实券商。依赖 PR #2，改动在 PR #3 审核；用户现已授权合并并按既有流程部署。
入场仍由用户手动决定，不实现 P1 自动选股或自动买入策略。

## 用户流程

- 新买单填写止损价并勾选“启用自动止损”，订单预览明确提示。未填价格或未勾选则不启用。
- 买单成交后，为该买入批次创建保护。不同买入批次可有不同止损，不会用一个新价格偷偷覆盖整个同标的持仓。
- 持仓后可通过“自动止损”区域启用、修改或停用该批次保护。价格须低于当前有效参考价、最多两位小数。
- 修改从服务器当前接受时刻生效，不检查生效前的价格；只处理生效后的完整5分钟区间。已触发而等待卖出的保护不能撤销或修改。若生效后行情仍有缺口，不能证明保护尚未触发，也暂不允许修改/停用。
- 手动减仓后，只保护该批次剩余数量；手动平仓则取消对应保护。
- 导出包含止损设定、触发、停用/延期和实际模拟成交证据，历史事件不可修改。

## 明确的 OHLC 模型

保护从买入成交根的**收盘标签之后**生效，不用买入根的最低价回填同根止损。
这意味着 V1 自动止损不覆盖入场第一根内的风险，不能宣称是实时券商挂单。日内修改同样不会检查横跨修改时刻的未完成区间，可能低估真实止损风险；严格执行研究需要进一步引入逐笔行情或在下一根边界切换时仍保留旧保护的模型，不能把当前练习收益当作严格策略验证。
若新买入时开盘价已经达到/低于自动止损价，拒绝入场，不制造“先买后立即按有利价卖出”。

| 情境 | 触发证据 | 模拟成交 |
|---|---|---|
| 生效后的常规K线开盘 ≤ 止损价 | 该根开盘标签与开盘价 | 若该根具备模型可成交性，按该开盘价减5bps不利滑点卖出 |
| 开盘 > 止损价，但最低价 ≤ 止损价 | 只有该根开/收盘区间，没有确切根内时刻 | 等该根完成后，按后续可成交K线开盘价减5bps卖出；不按止损价回填 |
| 平坦K线/无法判断流动性 | 可记录触及，但无模型可成交性 | 保持触发状态，等待后续可成交开盘 |
| 更早的常规K线缺失 | 无完整前缀证据 | 暂停检查，不跳过缺失区间挑选成交价 |
| 旧行情后到，候选卖出时间早于既有成交 | 无法安全重排账本 | 保存触发证据，将可成交起点推迟至当前观察之后，等待未来开盘 |

下一开盘可与上一根收盘标签相等，这是本模型声明的零反应延迟边界，并不是实盘最早可执行时间证据。
如果后续价格反弹，已触发的止损仍会按后续开盘卖出；不能看到反弹后撤销触发。固定费用和分级FIFO成本分摊沿用练习盘模型。

服务器可在稍晚刷新中重放已经授权的保护，模拟成交标签可能早于实际观察/写入时刻。
因此记录同时区分：

- 用户授权与保护生效时间；
- `stop_triggered.interval_open/interval_close`：触及证据所属区间；
- `exact_intrabar_time=null`：不会从 OHLC 伪造根内触发时刻；
- `stop_triggered.observed_at`：服务器实际记录该触发的时间；
- `fill.market_bar.open_time`：模型选定的模拟开盘；
- `fill.recorded_at`：实际写入账本时间。

原始信号的 `first_seen_time` / `confirmed_time` 不受此功能影响，仍不从极值时间推造。
自动止损成交标识为 `execution_reason=automatic_stop`，执行模型 `paper-v2-autostop`。
它不代表真实成交、真实即时监控能力或策略获利已验证。

## 与手动订单的先后

- 同一开盘的保护性卖出优先于手动订单。
- 触发卖出时取消同标的所有未成交手动卖单，避免它们再次卖出导致超卖；取消原因进入事件账本。
- 不自动撤销其他已明确提交的买单；它们仍按各自入场和资金检查执行。
- 自动卖出只使用对应批次成本；其他批次的保护和持仓不受影响。
- 无论用户修改/撤单请求是否有效，已经可以确认的市场事件必须持久化。实现使用事务 + 用户动作保存点，不能靠一个失败的修改请求回滚已经触发的止损。

## 后台运行与兼容

只有 `PAPER_TRADING_ENABLED=1` 且现有 APScheduler 可用时，生产接口才开放。
服务启动时注册独立 `paper_reconcile` 任务，每60秒调用 `sync_all()`；不需要用户保持网页打开，不改原行情流水线的15分钟周期。
实际检查频率不代表源行情每分钟更新。源行情延迟/缺失时，保护也会延迟；本版本仅处理常规交易时段。
用户已授权合并上线：受版本管理的 api.service 设置 PAPER_TRADING_ENABLED=1，由既有部署流程安装并重启服务；其他运行方式仍须显式启用。/api/jobs 提供 paper_enabled 与 paper_next_run 供上线核验。未更改部署脚本、密钥或券商配置。

数据库兼容升级：

- 为 orders 增加 `auto_stop`，旧记录全部默认为0；**旧 plan_stop 只作记录，不追溯激活**。
- 新增 protective_stops 表和索引，关联真实模拟持仓批次。
- 旧持仓可由用户显式启用，但只从新的接受时间开始检查，不回填过去的止损成交。
- 新手动买单仍采用原费用/价格模型；仅附属保护具备新自动行为。
- A股不开放，未改信号识别、评分、IBKR、实盘凭据或真实订单接口。
