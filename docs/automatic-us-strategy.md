# 美股自动策略模拟 V1

> 默认观察页现为独立V2风险管理账户，V1继续按本说明运行并可只读切换。V2的新增预算、组合限制和分类复盘见[新版说明](us-risk-review-v2.md)。原始API无version参数仍返回V1。

本次纠正手动练习盘的产品方向：服务器自动发现新信号、买入、卖出及止损，用户只查看运行情况。仅模拟，不连接券商。A股另行建设；旧手动账户及其API保留，但不进入新观察页，也不转移资金或持仓。

## 明确执行的规则

策略ID `us-daily-30m-v1`；独立初始资金100,000 USD；股票范围沿用现有美股监控池，纳指不交易。

| 环节 | V1规则 |
| --- | --- |
| 日线方向 | 只使用已完成日线，调用原 `analyze_level(..., level='daily')`，当前方向必须为up；这不表示最后线段永不重绘 |
| 市场环境 | 已完成SPY日线至少210根，最近收盘不低于SMA200；缺失、陈旧、未完成或日历不可用都为unknown，不允许新买入 |
| 入场 | 从系统建立基线后新观察到结构确认的30分钟2B/3B；PRE不入场 |
| 退出 | 新观察到结构确认的30分钟1S/2S/3S，清仓对应标的；取消该标的未成交买单；环境与日线过滤不阻止退出 |
| 排除 | 1B、BC_B/BC_S、中枢沿ZD_B/ZG_S不执行；旧confirmed触及语义仍在旧页面保留 |
| 去重 | PRE和正式信号共享极值身份；同一身份只决策一次；环境不符跳过后不追补，同源重复轮询及服务重启不重复下单 |
| 冲突 | 同一快照卖出优先，否则仅处理最新买点；存在不早于买点的已确认经典卖点时禁止入场；不同标的按代码排序，不声称是最优选股排序 |
| 仓位 | 每笔按初始资金10%预算买入整股，最多5个持仓/待入场标的；不加仓、不杠杆、不做空；费用、5%跳空资金预留照旧；跳空后实际市值可能偏离预算 |
| 止损 | 引用原 `chan2.STOP_PCT`（目前3%），以信号极值价为基准；低于当前参考价才提交。成交开盘已跌破止损则拒绝入场；成交根收盘后自动生效 |
| 参数地位 | 二买/三买筛选、仓位、缓冲及退出集合为本次公开的模拟V1参数，不是已验证的收益最优参数。调整规则应使用新策略版本/独立账本，不改写原历史 |

原检测器、信号数学定义、评分权重、原信号列表均未改动。自动策略不拿网站回算列表里的recent/score/confirmed直接当可交易证据。

## 数据与时序

`run2.py` 额外输出 `out/strategy_source_us.json`，`scripts/build_data.py` 原子发布到 `DATA_DIR/data/strategy_source_us.json`。

- schema为`us-strategy-source-v1`；`observed_at`记录股票下载请求前的服务器UTC时间，`generated`是生成时间，两者都不是信号识别时间。
- `symbols`为每只股票原始daily/30m OHLC与带时区标签；`benchmark`带独立请求时间及SPY日线原始OHLC。行情仍是原IEX数据口径。
- 缓存运行无真实请求时间，缺失/旧格式/失败来源一律unknown；发布源缺失时写入失效文件，不沿用旧的已知结果。
- 只取在请求前时间减15分钟之前结束的常规时段K线，使用XNYS日历处理假日、夏令时及提前收盘。15分钟是保守的数据稳定假设，并非供应商保证；后续修订仍可能发生。
- 原始历史前缀的重复、乱序、非有限数值、缺失预期常规K线、尾部未更新均拒绝该标的；日历失败不退回工作日猜测。盘前盘后30分钟数据不参与此策略。
- 数据请求时间早于当前超过45分钟，整个新信号决策暂停；已有止损与订单继续由独立账本任务处理。数据恢复后按当前真实观察时间决策，不回填中断期间交易。
- 每个标的第一次获得完整数据时建立历史基线；历史已存在的确认与PRE身份都不补单。之后新出现的确认或此前未消费的PRE转确认才可能决策。
- `strategy_observations.first_seen`和`first_confirmed`是**本监控服务实际第一次观察**及**第一次观察到结构确认**的时间；绝不声称是信号历史上最早可识别时间。初始历史信号记录本次观察时间，且始终不交易。
- 信号极值时刻保存在`signal_bar_time`；订单时间来自服务器实际接受时刻。决定之后下一根严格更晚的常规5分钟开盘才可模拟撮合，并在该K线完成后记录。
- 重绘/确认撤回会保留日志并撤销尚未成交入场；已经撮合的交易保持不变，不因未来失效过滤删除亏损记录，也不擅自增加“重绘即卖出”规则。

## 执行和只读边界

`AutomaticStrategy.tick`由服务端每60秒执行，最大并发1；原`PaperStore.sync_all`每60秒独立运行，负责待成交单和止损。两者通过SQLite事务串行协调，不依赖用户打开浏览器。

默认跟随已启用的模拟服务运行；运维可用进程环境`US_STRATEGY_ENABLED=0`单独停用新策略决策，既有待成交订单与保护止损仍由模拟账本处理，不应为了暂停新决策关闭整个`PAPER_TRADING_ENABLED`。本次不修改VPS部署脚本、凭据或IBKR配置。

`managed_accounts`将固定策略ID映射至单一服务器账户；不发放Bearer凭据，旧手动API也明确拒绝操作managed账户。`GET /api/strategy/us`只展示固定策略，不接受账户选择、交易或启动参数；POST为405。页面只发GET，不存/读旧手动账户凭据。读取报告不触发成交，但可记录当前可核验估值点。

`/api/jobs`新增`strategy_enabled`和`strategy_next_run`，报告含最近执行时间、源ID、状态与原因；手机页在心跳超过3分钟时显示等待调度，断网时明确标记旧数据。

账本以`strategy_created`保存完整规则，决策日志保存买入、卖出、跳过、历史基线及重绘原因；订单和提交事件保存同一份实际观察证据。信号成交新增`execution_reason=automatic_signal`、模型`paper-v3-strategy`，自动止损仍为`automatic_stop`。旧手动订单、字段和费用/撮合行为兼容。

止损沿用已上线模型：开盘跳空按开盘退出；盘中low触及时收盘确认、下一可成交开盘退出；缺失更早行情则等待，不挑有利价格；不推测成交K线内先后。详见[止损模型](paper-auto-stop.md)。

## 复现与验收

```bash
python -m unittest tests.test_strategy_source tests.test_automatic_strategy -v
python -m unittest tests.test_automatic_strategy.AutomaticTests.test_signal_automatically_enters_and_new_sell_exits_without_browser -v
python -m unittest discover -s tests -p 'test_*.py'
python -m tests.check_paper_calendar
node tests/test_paper_ui.cjs
```

以上专门案例用明确的人工行情顺序推进：先空基线 → 新2B观察/待成交 → 后续开盘买入 → 新3S观察（环境未知仍能卖出）→ 后续开盘平仓；每步检查真实SQLite事件、费用和观察时间。自动止损另有不读取报告、不打开浏览器的独立案例。人工价格只验证因果与账务，不是收益研究。

数据适配测试使用原检测器，修改未完成K线不会改变输出，缺口/坏价格/旧数据/日历缺失都会关闭决策。原P0逐根前缀重放仍可复现：`python -m scripts.replay_p0_example --output /tmp/p0-replay.json`，不等同于本V1回测收益验证。

## 风险与后续

| 等级 | 事项与当前处理 |
| --- | --- |
| P0已处理 | 历史极值冒充可交易时间：独立实时观察、首次基线、未来开盘撮合、不回填交易 |
| P0已处理 | unknown误判非熊、未完成K线、缺失行情：三态环境、日历前缀校验、延时缓冲、失效输入关闭买入 |
| P0已处理 | 重复/越权下单、未来重绘抹掉历史：事务幂等、只读managed账户、不可变事件及重绘日志 |
| P1待验证 | IEX延迟、修订和稀疏成交可能使标的长期unknown；缓冲与严格缺口要求会减少交易，应先看跳过日志，不能为追求交易量放松证据 |
| P1待验证 | 日线方向仍可能重绘；30分钟信号在实际首次观察时的有效性、延迟和样本量需要持续收集 |
| P1待验证 | 开盘OHLC撮合及5bp滑点不保证实盘流动性；15分钟数据缓冲、入场根无止损、跳空风险均需单独研究 |
| P1待建设 | 公司行动、分红、拆股、税费/结算与真实券商风险未模拟；已观察点回撤不覆盖盘中全部风险 |
| P1待验证 | 二买/三买、经典卖点、固定仓位和止损是否合理，需要冻结规则后的样本外验证，未声称任何收益已验证 |

后续候选筛选器建议独立版本评审：加入流动性/成交额、风险预算、距止损风险回报、日线结构质量、财报窗口与跨标的排序。不要在同一V1中悄悄调参后与旧收益混合比较。
